# Отложенные функции и технический долг

Этот файл — единый список идей и решений, которые мы уже обсуждали, но **не включаем в ближайшую реализацию**. Он нужен, чтобы не забыть их и не усложнять MVP раньше времени.

Правило: пункты из этого списка не реализуются автоматически. Перед началом каждой функции нужно уточнить приоритет, объём и критерии готовности.

## 1. Функции продукта на потом

- [ ] **Вход через Apple (Sign in with Apple).** В MVP используем email и пароль через Amazon Cognito User Pools. Позже добавить Apple как дополнительный способ входа, сохранив существующие аккаунты и привязку данных.
- [x] **Голосовой ввод и Siri / Apple Shortcuts.** Позволить добавлять слова и запускать отдельные действия голосом через iPhone. Сначала проверить возможности Shortcuts; полноценную нативную интеграцию не делать в MVP. _Реализовано как капча-эндпоинты `POST`/`GET /api/v1/capture` + гайд `/shortcuts`: диктовка через Apple Shortcuts шлёт текст в обычный import-пайплайн (`voice`-источник, попадает в review). Нативной Siri-интеграции нет — это веб-приложение; в проде нужна отложенная облачная аутентификация._
- [ ] **Импорт из изображений и OCR.** Извлекать слова и заметки с фотографий, скриншотов и изображений, после чего отправлять извлечённый текст в существующий процесс разбора и подтверждения.
- [ ] **Интеграция с ProgressMe.** Изучить доступные официальные способы экспорта или интеграции. Не строить решение на недокументированном доступе или обходе ограничений сервиса.
- [ ] **Социальные функции.** Обмен наборами слов, совместные списки или другие возможности для нескольких пользователей. Не нужны для персонального MVP.
- [ ] **Оплата и подписки.** Не добавлять биллинг, тарифы и ограничения по оплате, пока не появится подтверждённая потребность.
- [ ] **Другие изучаемые языки.** MVP ориентирован на испанский. Позже расширить модель и интерфейс на другие языки, не ломая существующие данные.
- [ ] **Нативное приложение для iOS.** Сначала сделать PWA, удобную на iPhone. Решение о нативном приложении принимать после реального использования PWA.
- [ ] **Дополнительные режимы практики.** Новые типы упражнений добавлять по результатам использования базовых сценариев, а не заранее.

## 2. Инфраструктура и эксплуатация — отложено до облачного развёртывания

- [ ] **Домен и HTTPS.** Отложить покупку/настройку домена до подготовки AWS-развёртывания. HTTPS обязателен до публичного использования; не передавать учётные данные по обычному HTTP.
- [ ] **AWS и Terraform.** Сначала разработка и проверка приложения локально. Затем описать инфраструктуру в Terraform и развернуть один личный облачный экземпляр.
- [ ] **GitHub Actions для облачного деплоя.** CI для проверок можно подготовить раньше; автоматический деплой в AWS подключать только после готовности инфраструктуры.
- [ ] **Резервные копии SQLite в приватный S3.** Настроить при переходе в облако. Копирование должно быть согласовано с режимом SQLite/WAL; нужно периодически проверять восстановление.
- [ ] **Мониторинг и оповещения.** На старте достаточно журналов приложения, проверки доступности и наблюдения за памятью/перезапусками. Более развитый мониторинг добавить при необходимости.
- [ ] **Переход с SQLite на PostgreSQL.** Не делать заранее. Вернуться к вопросу, если появятся существенная конкуренция за запись, несколько экземпляров приложения или ограничения SQLite.
- [ ] **Увеличение EC2.** Начать с `t4g.nano` как эксперимента. Если приложение нестабильно или возникает нехватка памяти, перейти на более подходящий размер. `t4g.nano` с 512 MiB RAM не гарантирует стабильную работу Next.js.

## 3. Архитектурные требования, которые нужно сохранить уже в MVP

Это не будущие функции, а ограничения, которые важно учесть сейчас, чтобы не затруднить дальнейшее развитие:

- [ ] **Заменяемый AI-провайдер.** Использовать внутренний интерфейс провайдера; не привязывать бизнес-логику напрямую к OpenAI. Реальный API-ключ хранить только на сервере.
- [ ] **Отделённый слой доступа к данным.** Использовать SQLite через Drizzle ORM и миграции; не разносить SQL по компонентам интерфейса. Это облегчит возможную смену БД.
- [ ] **Постоянное хранение SQLite.** Файл БД должен находиться на постоянном диске/томе, а не в эфемерном слое Docker-контейнера. Деплой не должен удалять данные.
- [ ] **Безопасная авторизация.** Для MVP использовать Amazon Cognito User Pools с email и паролем; не хранить пароли самостоятельно. Все операции с данными должны проверять владельца записи на сервере.
- [ ] **Минимизация расходов.** Не добавлять RDS, NAT Gateway, ALB и другие постоянно оплачиваемые компоненты без явной необходимости.
- [ ] **Сначала локальная разработка.** Локальный режим должен работать без AWS и без платного AI API — для тестов нужен mock AI provider.
- [ ] **Проверяемые миграции и восстановление.** Для изменений схемы использовать миграции; перед серьёзными обновлениями иметь проверенную возможность восстановить данные из резервной копии.

## 4. Когда пересматривать список

Пересматривать этот файл:
1. после завершения MVP;
2. после нескольких недель личного использования;
3. если появилась конкретная проблема, которую закрывает один из отложенных пунктов.

**Приоритет:** сначала надёжный импорт слов, удобная короткая практика, повторение по расписанию и сохранность данных. Остальное — после проверки этих основных сценариев.


## Решения, уточнённые позже

- Название проекта: Cards No Cards; тёмная тема.
- Пользователь меняет количество новых слов и продолжительность занятия в настройках.
- Выбор AI-модели должен быть доступен в настройках среди моделей, которые приложение действительно поддерживает.
- Статистика, офлайн-режим, уведомления, дополнительные способы входа и собственный домен — технический долг.
- Типы упражнений остаются TBD.
- Резервные копии SQLite отправляются в приватный S3 без сложных lifecycle-политик на старте; безопасное создание копии и проверка восстановления обязательны.
- Для AWS предпочтителен европейский регион рядом с Испанией. Указание `eu-east-1` нужно уточнить: это не стандартный ID региона AWS. Проверить варианты `eu-south-2` (Испания), `eu-west-1` (Ирландия) и `eu-central-1` (Франкфурт) по доступности сервисов и ценам до выбора.
